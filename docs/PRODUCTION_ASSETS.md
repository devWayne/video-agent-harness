## 3. 已验证的生产方法

### 3.1 先试控制路线，不把 H3 当必经层

H3 很适合动作、机位、端点和多参考控制草稿，但低质量草稿作为 V2V 底板可能把变形传给终稿。对每种内容先用一个代表镜头做 A/B：

1. `direct-keyframes`：原始关键帧 + 明确的运动 Prompt；
2. `control-video`：H3 草稿 + 原始外观参考；
3. 以终稿模型上的端点、元素运动、时序和品牌完整性决定全片路由。

控制层是可选证据，不是固定流水线税。

### 3.2 长片按语义和 Provider 上限分段

先做原子镜头，再把相邻且连续的 2–4 个镜头编成一个 Provider 支持的生成段。Bettr 使用 3 镜头/15 秒，是因为段内需要连续变化，同时又要限制一次失败的返工范围。

每个相邻段必须共享一个权威边界状态。边界优先使用原始设计页或批准端帧，不递归使用已经漂移的生成尾帧。

### 3.3 生成式动效和确定性修复分工

- 生成模型：深度、对象轨迹、物理聚合、镜头、节奏和光线。
- 确定性后期：精确端点、Logo、数字、字幕、裁切、过渡、音频对齐和编码。
- AI 4K：只对画面锁定后的母版执行一次；FFmpeg 只做媒体工程，不冒充超分模型。

### 3.4 旁白按 Cue 生产

脚本先绑定时间、帧号、字幕、朗读文本、语气和重音。每条 Cue 独立合成并保存原始音频、适配音频、计费字符、模型、音色、Seed 和请求证据。失败只重做单条；最终以画面主时钟合成母带。

### 3.5 保留可恢复证据

每个付费阶段至少保存：

- 输入哈希、模型和 Profile；
- Prompt 与有序参考角色；
- Provider Task/Run ID；
- 原始候选、后处理候选和选择理由；
- 输出规格与 SHA-256；
- 计费单位和已知重试浪费；
- 人工/Codex 评审和技术 QC。

Skill 可复制 [`production-run-record.template.json`](../skills/create-production-video/assets/production-run-record.template.json) 作为新的脱敏运行记录起点。
